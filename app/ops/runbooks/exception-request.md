# 例外の申請

ゲートの検出をすぐに直せないときに，期限付きで受け入れるための手順．
検出を直せるなら，例外にせずに直す．

## 例外にしてよい場合

- 脆弱な処理に到達しないことを確かめた．
- 直した版がまだ出ていない，または直した版に上げると壊れるので，検証の時間が要る．
- ゲートの誤検知である．

## 手順

1. 検出の内容(脆弱性の識別子，パッケージ，重大度)を確かめる．
2. 例外にしてよい理由を確かめる．到達しないことを理由にするなら，呼んでいない関数と，その確かめ方を書く．
3. `ops/exceptions.yaml`に例外を足すプルリクエストを作る．
   期限は，直す予定の日にする．基準値の`exception.max_days`を超えてはならない．
4. セキュリティ責任者が，理由と期限を確かめて承認する(CODEOWNERSで必須になっている)．
5. 期限が来る前に直すか，理由を確かめ直して期限を延ばす申請をする．

## 証跡

- `ops/exceptions.yaml`の変更履歴と，承認されたプルリクエスト．
- CIの`exceptions`ジョブの結果．
